# 新ワークスペース仕様書（v2.1・現行実装準拠・後方互換版）

状態：設計案（未実装）
現行の完全仕様は [spec-current.md](./spec-current.md) を参照。本書はそれを前提に、変えるところだけを定める。
変更方針：現行実装（pref ベースのストア、SessionStore 上のタブ所属）に合わせて前提を修正し、挙動を変える項目はすべて opt-in にした。

---

## 1. 目的

1つのウィンドウ内で、作業の文脈ごとにタブを分けて扱えるようにする。切り替えても、作成したワークスペースとタブは失われない。

## 2. 用語

| 用語 | 意味 |
|---|---|
| ワークスペース | 名前・アイコン・既定コンテナ・タブ群を持つ、文脈の単位 |
| ストア | ワークスペースの定義（順序・既定 ID を含む）を保存する、プロファイル単位のデータ。正本は pref `floorp.workspaces.v4.store` |
| スナップショット | ストアの世代付きバックアップ。`<ProfD>/workspaces/store-snapshots/` に置く |
| アーカイブ | 削除前の一時保管場所。`<ProfD>/workspaces/archive/` |
| 表示面（ウィンドウ） | ワークスペースを見るウィンドウ。選択中のワークスペースはウィンドウごとの状態 |
| タブ所属 | タブ属性 `floorpWorkspaceId`。正本は SessionStore |
| グローバル固定（Essential） | 全ワークスペースに出る固定タブ。**本仕様の対象外**（§9） |

## 3. 基本原則

1. **定義は常に残す**：ワークスペースの定義は、どの設定でも消えない。
2. **タブの復元は設定に従う**：復元は SessionStore と `browser.startup.page` に従う。ワークスペースが独自に判断しない。
3. **消さずに退避する**：削除はアーカイブへの移動が既定。完全削除は確認を挟む。
4. **挙動は変えない**：既存の挙動を変える機能は新設定で追加し、既存プロファイルは旧挙動を保つ。
5. **読み手を壊さない**：pref 形式に依存する箇所（ランタイムパッチ、OS サーバ API、設定ページ）が読めなくなる変更はしない。

## 4. データモデル

### 4.1 ストア（現行 v4 を拡張）

```
store {                          // pref: floorp.workspaces.v4.store
  schemaVersion?: 2              // 新規。無ければ v4 とみなす
  defaultID: UUID
  data: [[UUID, Workspace]]      // Map のシリアライズ形式を維持
  order: [UUID]
}

Workspace {
  name: string                   // 文字種制限なし
  userContextId: number          // 0 = コンテナなし（現行のまま）
  icon?: string | null
  color?: string                 // 新規・任意
  createdAt?, updatedAt?: number // 新規・任意。無い場合は不明のまま扱う
  isSelected?, isDefault?        // 現行互換のため残す。参照しない（正本は defaultID とウィンドウ内状態）
}
```

- フィールド名は現行の `userContextId` を使う（旧仕様の `containerId` は採用しない）。
- 追加フィールドはすべて任意とし、古い読み手が無視しても壊れないこと。
- `schemaVersion` が未知の大きい値なら、書き込みをせず読み取り専用で動く（将来版との相互運用のため）。

### 4.2 ウィンドウ状態（揮発）

- 選択中のワークスペースはウィンドウ内の signal（現行どおり）。永続データを置かない。

### 4.3 タブ所属

- 正本は SessionStore（`floorpWorkspaceId`、`floorpWorkspaceLastShowId`）。**ストアは TabRef を持たない**。
- 所属が無い・不明な ID のタブは、現行どおり選択中または既定のワークスペースに割り当てる。

### 4.4 保存方式

- 正本は pref のまま。
- 変更後にデバウンス（約 1 秒）して、ストア全体を `IOUtils` でスナップショットファイルへアトミックに書く（一時ファイルへ書いてリネーム）。最大 3 世代を残す。
- 変更がなくても 30 秒ごとの定期保存はしない（pref が変わらなければ書かない）。
- 起動時にストアを検証し、デコードに失敗するか空なのにスナップショットがある場合は、最新の有効なスナップショットから復旧する。復旧したことはコンソールに `[Workspaces]` 接頭辞で記録し、設定画面に一度だけ通知する。
- 現行の「空ストアなら New Workspace を作る」動作は、スナップショットが無い場合のみ行う。

## 5. 動作仕様

### 5.1 作成・名前変更・削除

| 操作 | 動作 |
|---|---|
| 作成 | 現行どおり。既定コンテナの選択は作成ダイアログに出す |
| 名前変更 | ID は変えない |
| 削除 | 既存のアーカイブ（`workspaces-archive-service.ts`）へ移動。保持期間経過後に自動消去（§6） |
| 完全削除 | アーカイブ内からのみ。確認ダイアログを表示 |
| 復元 | 元の ID と内容を戻す。同 ID が既存なら新 ID を発行して通知 |

### 5.2 切り替え

- 切り替えは表示中のウィンドウだけに効く（現行どおり）。
- **別ウィンドウで同じワークスペースを選んだとき**：既定は現行どおり（独立に選べる）。設定「同じワークスペースが開いていれば、そのウィンドウへ移る」を有効にした場合のみ、既存ウィンドウへフォーカスする。複数ウィンドウでの同時表示は本版では扱わない。
- **最後のタブを閉じたとき**：既定は現行どおり（`exitOnLastTabClose` の設定に従う）。新設定「最後のタブを閉じても、ワークスペースに留まる」を有効にした場合のみ、別ワークスペースへ自動切替せず、空の状態（置換タブ）を表示する。

### 5.3 タブを開く（コンテナ規則）

- 既定コンテナは、現行の解決関数 `getCurrentWorkspaceUserContextId()` を唯一の入口とする。
- 対象の経路（現行 11 経路）は一覧化し、各経路にテストを置く：
  1. `BrowserCommands.openTab` 2. `openTrustedLinkIn` 3. `openUILinkIn` 4. アドレスバー 5. コマンドパレット（URL を開く／Web 検索／ブックマーク） 6. ブックマーク 7. リンクの右クリック「別のワークスペースで開く」 8. 置換・空ワークスペース用タブ 9. 外部リンク（ランタイムパッチ） 10. スナップショット復元 11. 最初のタブ
- **アドレスバー経路は未検証**。段階 2 で実測し、漏れがあれば `openTrustedLinkIn` / `openUILinkIn` の経路に寄せる。
- 明示的にコンテナを指定された場合（コマンドパレットの選択など）は、それを優先する（現行どおり）。

### 5.4 固定タブ

- 本版では変更しない。ピン留めタブは通常タブと同じくワークスペースに属する。
- Essential は別仕様（§9）。

### 5.5 ウィンドウを閉じる・終了

- 現行どおり SessionStore に従う。ワークスペースの定義はストアにあるため、ウィンドウを閉じても消えない。
- 「そのウィンドウだけにあるタブ」をストアへ移す機能は本版では作らない（§9）。
- #1129（別ウィンドウで PWA が開いているとき、本体を閉じるとタブが隠れる）は、段階 2 で再現テストを作ってから原因を切り分ける。ワークスペース側の問題か Firefox 側かを先に確定する。

### 5.6 分割表示

- 分割は `floorpSplitViewGroupId` 属性で表現され、ワークスペースは認識しない（現行）。
- #2567（タブスタックを別ウィンドウへ移すと分割が消える）は、段階 2 で再現テストを作る。属性が移動先に残るかをまず実測する。
- 分割を維持できない場合は、その旨を通知する。

### 5.7 異常終了

- 起動時に §4.4 の検証と復旧を行う。
- スナップショットの書き込み中に落ちた場合、一時ファイルは無視し、直前の世代を使う。

## 6. 設定

追加する設定は設定画面に出す。about:config 専用の項目は作らない。

| 設定 | 既定（新規プロファイル） | 既定（既存プロファイル） |
|---|---|---|
| 同じワークスペースが開いていれば、そのウィンドウへ移る | 無効 | 無効 |
| 最後のタブを閉じても、ワークスペースに留まる | 無効 | 無効 |
| 削除したワークスペースの保持期間（日） | 30 | 30 |

- 保持期間は 1〜365 日。0 日（即時消去）は設定できない。
- 既存設定（`exitOnLastTabClose`、`manageOnBms`、`closePopupAfterClick`、`showWorkspaceNameOnToolbar`）の意味は変えない。
- **先に直すこと**：設定ページ側の既定値（`pages-settings/.../dataManager.ts`）とチャローム側の既定値（`data/old-config.ts`）が食い違っている（`showWorkspaceNameOnToolbar`、`closePopupAfterClick`）。どちらが実際の既定かを確定して揃える。
- 各セクションに「既定値に戻す」ボタンを置く。

## 7. 後方互換性

### 7.1 データ

- 移行元は 2 世代ある。
  - **11.x のファイル**：`<ProfD>/Workspaces/Workspaces.json`。現行の `data/migrate/migration.ts` が引き続き処理する。変更しない。
  - **v4 の pref**：`schemaVersion` が無いストア。読み込めるときは何も変換せず、必要になった時点で `schemaVersion: 2` を付けて書き戻す。
- v4 → v2 の変換前に、スナップショットを 1 世代作る（これを旧 `workspaces-v1.bak` の代わりとする）。
- 変換に失敗したら、v4 のまま動き続ける。

### 7.2 挙動

- 既存ユーザーの挙動は変わらない。新機能はすべて opt-in。
- ランタイムパッチ・OS サーバ API・設定ページは、v4 形式をそのまま読める状態を保つ。

### 7.3 ロールバック

- 追加フィールドは任意なので、旧バージョンに戻しても読める。スナップショットは手動復旧用に残す。手順はサポート用に別途用意する。

## 9. 段階的な移行

1. **保存の堅牢化**：スナップショット、起動時検証と復旧、`schemaVersion`、設定既定値の統一。（T1、T7、T8、T10）
2. **再現テストの整備**：T3・T4・T6 を実測し、原因を確定する。コードは変えない。
3. **ウィンドウとコンテナ**：確定した原因の修正、フォーカス規則と最後のタブの opt-in 設定。（T2、T3、T4、T5、T6）
4. **削除と退避**：保持期間と自動消去、復元時の ID 衝突処理。（T9）

各段階はリリースを分け、前段階の受け入れ条件を満たしてから次へ進む。

### 本版の対象外（別仕様）

- Essential（グローバル固定）：現行に概念が無く、新規の大機能。上限数を決めてから別仕様にする（提案：8 個）。
- タブ所属のストア化（SessionStore からの分離）。
- 複数ウィンドウでの同時表示、タブ並び順の同期。
- ワークスペースごとの既定検索エンジン、デバイス間同期、Arc 型の表示。
- Firefox 本体の固定タブの仕組みの変更。

## 10. 決定済みの事項

- アーカイブ保持期間の 0 日は不可（最小 1 日）。
- Firefox 本体の固定タブとの関係は、Floorp 側で再現しない。

## 11. 未決事項

- スナップショットの保存先を `<ProfD>/workspaces/` 配下にしてよいか（バックアップ・同期ツールとの関係）。
- `isSelected` / `isDefault` を将来削除するか。
- `browser.startup.page` が 3 以外のユーザーで、ワークスペース所属が失われたときの扱い（現行は既定ワークスペースへ）。
